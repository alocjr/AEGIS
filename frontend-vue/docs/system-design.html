01

Resumo executivo

O frontend-vue entrega quatro produtos dentro de um mesmo shell: a mentoria, o AI Hub estratégico, a Governança de IA e o painel administrativo. A arquitetura que sustenta isso é sólida. A camada que o usuário vê não acompanhou.

O que está certo e deve ser preservado: nenhuma view chama fetch diretamente — tudo passa por api/client.ts, com erro unificado em ApiError. Zero any em 30.898 linhas. Zero v-html. Sessão por cookie HttpOnly, nunca token em localStorage. Toda a autorização de navegação vive num único beforeEach, com três eixos independentes. E lib/strategicMapGraph.ts mostra que o time sabe extrair regra de domínio para fora da view — 1.201 linhas de lógica pura e testável.

O que destoa: não existe biblioteca de componentes. 35 views para 5 componentes. Cada tela reimplementou botão, card, modal, tabela e estados de carregamento com CSS próprio — 13.288 linhas de CSS dentro de arquivos .vue, 43% de todo o código-fonte. Disso decorre o resto: três sistemas de tokens que dão dois dourados e duas serifas à mesma marca, 82 cores fora do sistema, 27 tamanhos de fonte, e a cor de texto secundário mais usada do produto (227 ocorrências) com contraste de 2,29:1 — menos da metade do mínimo WCAG.

Dois bloqueios de entrega: o build de produção não passa (48 erros de tipo registrados em tsc5.txt), e o cache está desligado para todos os assets com hash.

Regra de dependência respeitada

  • views → api → client. Nenhuma view chama fetch diretamente. A única exceção é lib/track.ts, e é intencional: telemetria fire-and-forget que não pode propagar erro de rede para a UI.
  • ApiError { message, code, status } unifica o contrato de erro, com suporte ao formato detail: { code, message } do backend para erros de negócio com código estável.
  • Um 401 em qualquer chamada que não seja sonda de sessão dispara logout e redireciona para /401 — regra única, em api/client.ts.

Modelo de acesso — três eixos

Toda a autorização de navegação vive num único router.beforeEach. É o desenho correto e vale documentá-lo explicitamente, porque é a regra mais sutil do produto.

EixoFonteEscopoFalha leva a
Sessãocookie HttpOnly → auth.loadUser()12 prefixos protegidos/401
Papel · plataformauser.is_admin/admin/*/401 ou /
Papel · organizaçãouser.is_org_admin/organizacao/*/401 ou /
Ferramenta liberadauser.tools[] × lib/tools.ts6 ferramentas do AI Hub/acesso-negado?tool=…
E-mail verificadouser.email_verifiedrotas protegidas/login

Há ainda uma regra de destino: em /, um usuário logado com trilha vai para /programa; sem trilha — caso típico de membro criado por um admin de organização — cai na primeira ferramenta liberada segundo TOOL_HOME_ORDER. É o que permite vender o AI Hub sem a mentoria.

As seis ferramentas: maturity → /ai-maturity, swot → /swot, canvas → /projetos, okr → /okrs, strategic_map → /mapa-estrategico, governance → /governanca. A mentoria não entra nesse eixo: usa course_slugs.

05

A cadeia de valor rastreável

O diferencial do produto não são as telas — é o fato de que os artefatos se referenciam. Do diagnóstico ao mapa, cada etapa consome a anterior por identidade, não por cópia.

  Maturidade ──► SWOT ──► TOWS ──► OKR ──────┐
   (4 dimensões)  (4 quadrantes) (4 cruzamentos)  ├──► Mapa Estratégico
                     └────► AI Canvas ────────────┘     lentes pan/ges/lin
                                                        linhagem por nó
                     Governança ──► Gates ──► Evidências
  • AiMaturityDetailView chama createSwotFromMaturity — o diagnóstico vira SWOT sem redigitação.
  • SwotAnalysisView reconstrói o TOWS sob demanda: updateSwotAnalysis(payload, id, { rebuildTows }).
  • OkrCycleEditorView e ProjetoCanvasView importam iniciativas TOWS diretamente da SWOT ativa.
  • MapaEstrategicoView consome fetchStrategicMap e monta o grafo em lib/strategicMapGraph.ts — 1.201 linhas de lógica pura, com lineageOf() para rastrear a linhagem de qualquer nó.

O padrão a replicar

  • strategicMapGraph.ts é a única parte do projeto onde a regra de domínio foi extraída da view. É testável, reutilizável e deixou MapaEstrategicoView com metade do tamanho que teria. Este é o modelo para os outros seis god components.

Design System — o que destoa

assets/main.css define 32 tokens, e todos os 32 são usados — nenhum token morto. O problema não é o que existe: é o que foi criado por fora.

CríticoDS-01Três sistemas de tokens concorrentes — a marca renderiza dois dourados e duas serifas

AiMaturityView.vue:591-613 e SwotAnalysisView.vue:1168-1178 redefinem tokens globais com outros valores. O mesmo nome significa coisas diferentes conforme a rota:

TokenGlobal (main.css)Maturidade / SWOTMapa EstratégicoCanvas
--gold#9b7e46#c6a15bherda—
--navy#0c2340 (via --k0)#0e1b33#0c2340—
--serifPalatino Linotype…Cambria, Hoefler Text…herda—
--ink—#242a33—#12232e
--line—rgba(198,161,91,.32)—#d8d2c6
--muted—#6e6a60var(--k3)—

Consequência prática: SWOT e Maturidade são visualmente um produto; Mapa, Governança e Admin são outro. Um cliente que percorre a cadeia atravessa duas identidades.

Ajuste

Decidir qual é a marca — a leitura editorial de SWOT/Maturidade é a que mais se aproxima de premium, executivo e sóbrio. Promover esses valores a main.css sob nomes explícitos (--brand-navy, --brand-gold, --brand-serif, --ink, --line, --muted), remover os quatro blocos locais e migrar as demais telas. Proibir redefinição de token global em <style scoped> na revisão de PR.

AltoDS-0282 cores hex distintas em 346 ocorrências fora do sistema

Concentração: SwotAnalysisView 52 · ProjetoCanvasView 48 · ProjetosListView 47 · AiMaturityView 38 · GovernanceInventoryView 14 · GovernanceSystemView 14 · MapaEstrategicoView 13.

Ajuste

Fechar uma paleta semântica de ~24 tokens (4 superfícies, 4 níveis de texto, 3 bordas, 4 dimensões de maturidade, 5 níveis, 4 estados) e substituir por codemod. Travar com stylelint (color-no-hex) no CI para não voltar.

AltoDS-03Sem escala tipográfica — 27 tamanhos, incluindo fracionários

13px (129×), 12px (125×), 14px (117×), 11px (94×), 10px (29×)… e 12.5px, 11.5px, 10.5px, 9.5px, 13.5px, 14.5px, 8px. Meio pixel não é decisão de design — é resíduo de ajuste visual manual.

Ajuste

Escala de 8 degraus em tokens: --fs-xs 11 / --fs-sm 12 / --fs-base 13 / --fs-md 14 / --fs-lg 16 / --fs-xl 20 / --fs-2xl 26 / --fs-3xl 34. Zero fracionários.

AltoDS-05Terceira família tipográfica, carregada de dentro de um componente

ProjetoCanvasView.vue:1155 faz @import url('https://fonts.googleapis.com/css2?family=Space+Grotesk…') dentro de <style scoped>, e usa a fonte em 13 declarações. É a única view com identidade tipográfica própria, e o @import é uma requisição render-blocking disparada no meio do CSS da rota.

Ajuste

Se Space Grotesk entra na marca: <link rel="preconnect"> + preload no index.html e token --display. Se não entra: remover as 13 declarações e o @import. Não deixar como está.

MédioDS-0413 raios de borda e 31 sombras distintas

Raios: 1, 2, 3, 4, 5, 6, 7, 8, 10, 12, 20, 99, 999px. Sombras: 31 valores únicos, incluindo três variações quase idênticas de 0 4px 1Xpx rgba(12,35,64,.08).

Ajuste

--r-sm 4 / --r-md 8 / --r-lg 12 / --r-pill 999px; e --shadow-1 (repouso), --shadow-2 (elevado), --shadow-3 (modal).

MédioDS-06Variáveis usadas sem definição — uma delas é bug silencioso

MateriaisView.vue:287 → color: var(--k2). --k2 não existe — a escala pula de --k1 para --k3. A declaração é inócua e o texto herda a cor do pai, sem erro visível.

Além disso: LoginView.vue:21 usa var(--navy-deep, #0C1827) e os dois admins de landing usam var(--bg, #f7f5f0) em 4 pontos — funcionam apenas pelo fallback.

Ajuste

Definir --k2 (ou trocar a chamada por --k1) e promover --navy-deep e --bg a tokens reais.

MédioDS-07Oito larguras de página diferentes

520 · 860 · 900 · 920 · 980 · 1000 · 1100 · 1200px, sem regra que explique a escolha.

Ajuste

Três larguras: --w-read 860px (leitura e formulário), --w-app 1120px (painéis e tabelas) e full-bleed (mapa, canvas).

Ajuste — a intervenção de maior alavancagem do projeto

Criar src/components/ui/ com 12 primitivos, nesta ordem de impacto:

AltoAR-02Sete god components somam 11.722 linhas

SwotAnalysisView 2.255 · ProjetoCanvasView 2.105 · ProgramaView 1.949 (207 seletores de classe) · MapaEstrategicoView 1.624 · AiMaturityView 1.318 · OkrCycleEditorView 1.246 · QuizView 1.225.

Ajuste

O projeto já tem o remédio: lib/strategicMapGraph.ts tirou 1.201 linhas de regra de domínio de dentro da view. Replicar — lib/swotModel.ts, lib/canvasModel.ts, lib/maturityScore.ts — e quebrar cada view em seções (SwotQuadrant.vue, TowsMatrix.vue, CanvasBand.vue). Meta: nenhuma view acima de 600 linhas.

MédioAR-04Domínio duplicado no cliente
  • Membros da organização em dois módulos e dois tipos: orgAdmin.listOrgMembers() → /api/org-admin/members (OrgMember) e governance.listOrganizationMembers() → /api/governance/organization-members (OrganizationMember).
  • Dimensões de maturidade em 4 lugares: AiMaturityDetailView:40-43 (hex cru), AiMaturityView:47-56 (vars locais), MapaEstrategicoView:931-934 (vars locais), strategicMapGraph:150-154 (classes CSS).
  • Rótulos dos quadrantes SWOT em 4 views: GovernanceSystemView:38, MapaEstrategicoView:60, ProjetoCanvasView:216, SwotAnalysisView:66.
Ajuste

src/lib/domain/ como fonte única: MATURITY_DIMENSIONS (id, rótulo, abreviação, cor), SWOT_QUADRANTS, TOWS_META. Parte já vive em api/swotAnalysis.ts — consolidar ali ou migrar tudo, mas em um lugar.

MédioAR-07Duas stacks de frontend no mesmo produto

A landing é HTML/JS estático (public/lp.html + lp.js, além de calc.html, tutorial-tokens.html, universo-da-ia-interativo.html, ficcao-realidade-catalogo-interativo.html) e o app Vue a embute num <iframe> (LandingView.vue), passando loginBase e apiBase por querystring.

Custos: marca e componentes existem duas vezes; a telemetria precisa de exceção documentada (lib/track.ts exclui a rota Landing para não contar duas vezes); e a home do app não é uma página indexável.

Ajuste

Manter a LP estática é legítimo (performance e CSP). Mas servir / diretamente no edge/backend e remover a rota Landing do router, em vez de encapsular num iframe.

MédioAR-05types/ cobre só um domínio dos treze

types/index.ts tem 72 linhas e cobre apenas o domínio "curso". Os outros 12 domínios declaram tipos dentro de api/*.ts (governance 32, admin 25, maturity 18…). Dois lugares para a mesma decisão.

Ajuste

Manter a convenção majoritária (tipo junto do módulo de API) e esvaziar types/index.ts, movendo os tipos de curso para api/course.ts. Ou o inverso — mas não os dois.

BaixoAR-06Nomenclatura da API mistura três verbos e dois idiomas

Verbos: fetchX (18) · getX (10) · listX (9). Idioma: aprovarPortfolio, confirmarProfundidade, liberarEncontro, getProfundidade, emptyPilares convivem com createGate, listAiSystems. Endpoints: /api/swot-analysis, /api/canvas-projects, /api/org-admin (kebab) vs /api/okrs, /api/maturity, /api/governance.

Ajuste

Convenção list / get / create / update / delete e identificadores em inglês (português apenas em rótulos de UI). O padrão de endpoint é contrato do backend — registrar como dívida conjunta, não mudar unilateralmente.

08

UX e fluxo

AltoUX-01Perda de dados silenciosa em quatro editores

SWOT, Canvas, Maturidade e Governança não avisam ao sair com gravação pendente. Só OkrCycleEditorView registra beforeunload e onBeforeRouteLeave. Em telas onde o usuário passa meia hora preenchendo um diagnóstico, um clique na topbar pode descartar a última edição.

Ajuste

Guarda embutida no useAutosave (AR-03) — resolve os quatro de uma vez.

MédioUX-02Estados de carregamento, vazio e erro artesanais em 28 telas

28 views declaram loading, 26 declaram error, cada uma com marcação e microcópia próprias: "Carregando..." (18×) convive com "Carregando…", "Carregando trilhas...", "Carregando o mapa…", "Carregando diagnóstico…" — reticências ASCII e Unicode misturadas no mesmo produto. Nenhuma tela usa skeleton.

Ajuste

<StateBlock :state> com cópia padrão e skeleton opcional. Guia de microcópia: reticências tipográficas (…) sempre; "Carregando…" sem complemento, porque o contexto já é a tela.

MédioUX-03Modais sem contrato de acessibilidade

8 views implementam modal; apenas 2 tratam Escape; nenhuma tem focus-trap, retorno de foco ao fechar, ou role="dialog" + aria-modal de forma consistente. Com teclado, o foco continua navegando o conteúdo atrás do modal.

Ajuste

AppModal único: role="dialog" aria-modal="true", trap de foco, Escape, restauração do foco de origem, inert no conteúdo de fundo e bloqueio de scroll.

MédioUX-05Dois padrões de navegação — e uma exceção sem par no menu

A área logada usa topbar fixa de 64px com pílulas; /admin usa sidebar escura de 220px sem topbar, sem marca e sem caminho de volta para as ferramentas do AI Hub (só um "← Início"). São dois produtos visuais para o mesmo usuário.

Além disso, em Topbar.vue:40-50 o link do SWOT é o único que não é RouterLink: é <a href="/swot"> com preventDefault, router.push manual e fallback window.location.assign('/swot'). Os outros 8 itens são RouterLink simples.

Ajuste

Unificar o shell: mesma topbar em todo o produto, com sidebar contextual dentro do /admin. E converter o item SWOT em RouterLink — se o try/catch existe por causa de uma falha real de navegação, tratar a causa (provavelmente o parâmetro opcional /swot/:id?), não o sintoma.

MédioUX-04Menu do admin não reflete o router — e duas telas são stubs em produção

AdminLayout.vue expõe 7 destinos; o router declara 10 rotas em /admin. /admin/alunos e /admin/progresso só existem por URL direta — e ambas são placeholders de 14 linhas: "Gestão de alunos (em migração)" e "Progresso dos alunos (em migração)", servidos em produção.

Ajuste

Concluir ou remover as duas telas; derivar o menu de uma constante compartilhada com o router, para que menu e rotas não possam divergir de novo.

MédioUX-07Não existe rota 404

O router não declara catch-all. Qualquer caminho inválido resulta em tela em branco dentro do layout.

Ajuste

{ path: '/:pathMatch(.*)*', name: 'NotFound', component: NotFoundView }, reaproveitando o layout de estado de acesso do UX-06.

BaixoUX-06Dois tratamentos visuais para o mesmo tipo de evento

/401 é uma ilustração de tela cheia sobre #0c1827, com botões em hex cru (#9b7e46, #b8975a, #e2e2e7), sem topbar e sem tipografia da marca. /acesso-negado é um card claro, discreto, com var(--serif). Mesma família de evento — acesso barrado — resolvida de dois jeitos opostos.

Ajuste

Um AccessStateLayout com variantes 401, tool-disabled e 404.
